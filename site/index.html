Transparent grading

Ten points. Seven firmware dimensions. No hidden criteria.

Each task owns a ten-point rubric. Firmware tasks use the shared firmware-v1 profile, with every prompt requirement assigned to one dimension so a single defect is not counted twice.

01

Functional correctness

Interfaces, state transitions, successful paths, and outputs.

02

Bounded resource use

Memory, storage, allocation, alignment, and buffer limits.

03

Timing behavior

Deadlines, wraparound, latency, lock-freedom, and blocking.

04

Concurrency safety

Ownership, atomics, ordering, interrupts, RTOS interaction, and races.

05

Fault recovery

Invalid input, partial failure, retries, timeouts, and safe states.

06

Portability

Target assumptions, language rules, alignment, and undefined behavior.

07

Clarity & validation

Reviewable code, explicit assumptions, and focused tests.

The scoring rule

Executable checks are evidence for the affected dimensions—not an automatic score.
01

Blind model identity and verify prompt, rubric, profiles, and environment.

02

Run declared compilation, tests, mutations, and sandbox validation.

03

Award partial credit by dimension and record a concrete reason per deduction.

04

Give zero for contradicted or safety-critical requirements in their owning dimension.

Quick start

Run your first firmware comparison.

Node.js 22+ runs the dependency-free harness. Generating answers also requires one configured provider runtime or OpenAI-compatible endpoint; each validator declares its own language toolchain.

1

Clone and configure

Create a private model configuration. It is ignored by Git and must never be committed.

2

Choose and authenticate a provider

The example uses Codex and gpt-5.6-luna. Claude Code, OpenCode, and OpenAI-compatible endpoints are also supported; see the provider setup instructions.

3

Run one constrained sample

Start with one run, one model, and one or two task IDs. Run 1 writes one record per pair directly under results/.

4

Extract and validate

The answer is written into fixture-owned ignored paths, then compiled and tested under its declared contract.

01 / setup — Codex example
# Node.js 22+
git clone https://github.com/arjun7965/llm-firmware-benchmark.git
cd llm-firmware-benchmark
cp models.example.json models.local.json
codex login
02 / benchmark
npm run benchmark -- \
  --models gpt-5.6-luna \
  --suites firmware \
  --tasks embedded-ring-buffer \
  --tasks firmware-state-machine \
  --runs 1 --concurrency 2
03 / validate one answer
npm run fixture:extract -- \
  --result results/embedded-ring-buffer--gpt-5.6-luna.json

npm run fixture:validate -- \
  --task embedded-ring-buffer

Repeat the same matrix

Generate runs 2 and 3 with the same model and task filters. Repeated records are written under results/run-2/ and results/run-3/.

npm run benchmark:repeats -- \
  --models gpt-5.6-luna \
  --suites firmware \
  --tasks embedded-ring-buffer \
  --tasks firmware-state-machine \
  --runs 2,3 --concurrency 2

Score, then summarize

Copy the score template, then record each 0–10 total under its task ID for every completed model run.

cp repeat-scores.example.json repeat-scores.json
# Edit repeat-scores.json, then:
npm run summarize

Publish safely

Never publish raw results. Export the allowlisted projection and inspect every file marked reviewRequired.

npm run export:public -- \
  --input results \
  --output public-results
